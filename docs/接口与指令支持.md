# 接口与指令支持

## 1. 指令范围
| 类别 | 已实现指令 |
|---|---|
| 上位立即数 | LUI、AUIPC |
| 跳转 | JAL、JALR |
| 分支 | BEQ、BNE、BLT、BGE、BLTU、BGEU |
| 加载 | LB、LH、LW、LBU、LHU |
| 存储 | SB、SH、SW |
| 立即数运算 | ADDI、SLTI、SLTIU、XORI、ORI、ANDI、SLLI、SRLI、SRAI |
| 寄存器运算 | ADD、SUB、SLL、SLT、SLTU、XOR、SRL、SRA、OR、AND |
| 顺序与环境 | FENCE、FENCE.I、ECALL、EBREAK |
| 额外的有限CSR支持 | CSRRW/CSRRS/CSRRC及三个立即数版本，MRET |

硬件原生完整支持 RV32I 基础整数规范及 FENCE.I 指令缓存同步屏障，未实现 M、A、C、浮点及虚拟内存（乘除由编译器 RV32I 运行库软件模拟实现）。FENCE 指令无需额外停顿（处理器采用单发射、内存事务顺序完成且无乱序访存）；FENCE.I 指令通过硬件冲刷取指流水线并使 I-Cache 全行原子失效，保障自修改代码与数据-指令强一致性。

## 2. CSR与中断异常机制
已实现标准机器模式CSR：
- `mstatus`(0x300)：MIE(全局中断使能位3)、MPIE(先前中断使能位7)、固定MPP=2'b11(Machine模式)。
- `mie`(0x304)：MEIE(外部中断使能位11)、MTIE(定时器中断使能位7)、MSIE(软件中断使能位3)。
- `mip`(0x344)：MEIP(外部中断未决位11)、MTIP(定时器中断未决位7)、MSIP(软件中断未决位3)。
- `mtvec`(0x305)：bits[31:2]为BASE向量基址；bits[1:0]为MODE（`2'b00`为Direct直接模式，所有陷阱跳转至BASE；`2'b01`为Vectored向量化模式，异步中断按 `BASE + 4 * cause` 索引向量表跳转，同步异常仍跳转至BASE）。
- `mscratch`(0x340)、`mepc`(0x341)、`mcause`(0x342)、`mtval`(0x343)，以及只读性能计数器 `cycle/cycleh/instret/instreth`。

**中断仲裁与响应流程**：
- 优先级仲裁：外部中断 (MEIP, cause=0x8000000b) > 软件中断 (MSIP, cause=0x80000003) > 定时器中断 (MTIP, cause=0x80000007) > 同步异常。
- 响应陷阱时：硬件自动将当前PC保存至 `mepc`，设置 `mcause`，将 `mstatus.MIE` 保存至 `MPIE`，清除 `MIE`（关中断），根据 `mtvec` 模式跳转处理函数。
- 执行 `MRET` 时：硬件恢复 `mstatus.MIE <= MPIE`，设置 `MPIE <= 1`，将PC重定向回 `mepc`。

**同步异常覆盖**：指令目标未对齐0、取指访问错误1、非法指令2、EBREAK3、加载未对齐4/访问错误5、存储未对齐6/访问错误7、ECALL(M)11。陷阱保存PC/原因/值，冲刷年轻指令后转mtvec。错误访存不发写操作。

## 3. 内存布局
统一RAM：0x00000000～0x0000ffff，64 KiB；代码、rodata、data、bss均在RAM，启动程序清零bss，栈顶0x10000，链接时至少保留8 KiB栈空间。固件映像包含data初始化，无需Flash→RAM复制。

| 地址 | 名称 | 读写说明 |

| 0x20000000 | UART_TX | 写低8位；支持低字节或整字；忙时总线等待 |

| 0x20001000 | GPIO_OUT | 读写低8位，固定输出 |
| 0x20001004 | GPIO_IN | 只读同步后的8位输入 |
| 0x20002000/04 | CYCLES_LO/HI | 64位复位后周期计数；软件高-低-高一致读取 |

| 0x20002058/5c | BTB_MISSES_LO/HI | 64位BTB分支预测失误次数计数器（只读） |
| 0x20003000 | CAP_CONTROL | 写bit0启动、bit1取消；同时置位时取消优先 |
| 0x20003004 | CAP_STATUS | bit0 BUSY、bit1 DONE、bit2 ERROR、bit3 TRIGGERED |

| 0x2000300c | CAP_LENGTH | 样本数1～1024 |

## 6. 存储系统与高级控制逻辑

### 6.1 2路组相联指令Cache与数据Cache (I-Cache & D-Cache)
- **容量与拓扑**：I-Cache 与 D-Cache 均为 1 KB 容量，结构为 32 组（Sets）× 2 路（Ways）× 16 字节（4个32位字）每 Cache 行。
- **总线突发传输（Burst Transfer）**：当 Cache 发生缺失（Miss）时，硬件状态机发起 4 字突发读取（Burst Fill），一次性自 RAM 读出对齐的 16 字节缓存行并重填至目标路。
- **替换策略**：每组配备 1 位伪 LRU（Least Recently Used）标记，命中或分配更新对应标记，确保热点数据常驻。
- **一致性与写策略**：
  - D-Cache 采用 **Write-Through（直写）** 配合 **Write-Allocate（写分配）** 策略：所有写操作直达底层的物理 RAM；若写命中 D-Cache，硬件按字节写掩码（`wstrb`）同步更新数据阵列对应行，保持缓存数据为最新值；若写缺失，状态机先发起 4 字突发读取重填分配新行，再提交写操作与更新行内容。
  - **Snoop Invalidation 硬件监听**：当 D-Cache 执行写操作时，若写地址同时处于 I-Cache，硬件自动废弃 I-Cache 对应缓存行，保障自修改代码与数据-指令强一致性。
  - **MMIO 旁路直通**：所有非 RAM 区间（0x20000000 及 0x30000000 采集缓冲）严格旁路 Cache，保证外设寄存器时序精确性。

### 6.2 动态分支预测器 (BTB + 2-bit 饱和计数器)
- **预测结构**：32 项直接映射分支目标缓冲（Branch Target Buffer, BTB），每项记录 25 位 PC 标记（Tag）、32 位跳转目标（Target PC）、有效位（Valid）与 2 位饱和计数器（00: 强不跳转, 01: 弱不跳转, 10: 弱跳转, 11: 强跳转）。
- **推测取指与验证**：
  - 在 IF 阶段，硬件以 PC 检索 BTB，若命中且计数器 $\ge 2$，推测预测跳转并无缝重定向 `fetch_pc`。
  - 在 EX 阶段，分支比较器得出真实跳转决策并验证预测：若预测命中，流水线以 **0 气泡 / 1 CPI** 零开销连续执行；若预测失误，冲刷 IF 级推测指令，重定向至正确 PC 并更新饱和计数器与目标地址。


### 6.3 缓存数据 RAM 原生 DRM 映射适配
针对 PDS 综合工具对 RAM 推断模板的严格要求，将数据 RAM 拆分为独立的标准同步 RAM 模块 `rv32la_cache_data_way`：
- **接口契约**：单时钟 `clk`，芯片使能 `cs`，写使能 `we`，4 位字节写掩码 `wmask[3:0]`，5 位行索引 `addr[4:0]`，32 位输入 `din` 与同步输出 `dout`；
- **原生 DRM 映射**：读时延严格为 1 个时钟周期，写操作在时钟上升沿根据字节使能进行按字节写入，满足 FPGA 原生专用块 RAM 的推断特征；
- **寻址空间规范**：以 64 KiB 物理 RAM 空间为基准（地址 bits[15:0]），Bits[15:9] 作为 7 位 Tag，Bits[8:4] 作为 32 组 Set 索引，Bits[3:2] 作为行内 4 字偏移，Bits[1:0] 为字节偏移，消除冗余的高位比较器延时。
